# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CleanAir is STM32F446RE (Nucleo-64) firmware for an AC vent fan controller that reads air-quality sensors (SPS30 particulates, BME680 + Bosch BSEC2, MQ131 ozone, MiCS-4514 CO/NO2) and phase-cuts an AC fan motor via a TRIAC based on a safety state machine. See `README.md` for the hardware architecture, pin mapping, and control-loop diagrams — read it before making hardware-facing changes (peripheral assignments, timing, safety thresholds).

## Build

This is a bare-metal ARM Cortex-M4 project cross-compiled with `arm-none-eabi-gcc`/`g++` (must be on `PATH`) and built with CMake + Ninja via presets:

```sh
cmake --preset Debug        # or Release
cmake --build build/Debug   # or build/Release
```

There is no test suite, linter, or `main()` entry point runnable on a host — this firmware only runs on the target MCU. "Testing" a change means building successfully and, when touching sensor/motor logic, reasoning through the FreeRTOS task and ISR flow described below and in `README.md`.

Flashing/debugging is done through CLion's ST-Link integration (this is a CLion-managed project, per `build/Debug/.gitignore` and `.idea/`); there is no checked-in flash script.

Do not hand-edit HAL init code generated by STM32CubeMX (`Core/Src/main.c`, `stm32f4xx_hal_msp.c`, `cmake/stm32cubemx/`, `.mxproject`, `clearair.ioc`) — regenerate from `clearair.ioc` in STM32CubeMX instead, since manual edits are overwritten on the next regeneration. Peripheral/pin changes belong in the `.ioc` file first.

## Architecture

- **C vs C++ boundary:** CubeMX generates C code (`Core/Src/main.c`, HAL, FreeRTOS task stubs). All application logic lives in C++ under `device/*` and is wired in via `extern "C"` task-handler trampolines defined in `Core/Src/cpp_main.cpp`. Each `xTaskHandler` function (e.g. `bmeTaskHandler`) suspends itself immediately, then blocks in the corresponding `SensorX::taskLoop()` — the task is later resumed explicitly once `configure()` succeeds in `appStartDefaultTask`.
- **Per-sensor modules (`device/<name>/`):** Each sensor/actuator is its own static CMake library (`bme68x`, `co1no2`, `fanmotor`, `o3sensor`, `particle`) with `inc/` and `src/`, built by `device/scope-share.cmake`'s `STM_SET_LIBNAME()` macro (library name = directory name). A module typically has a `task_*` class (owns the FreeRTOS task loop, derives from `BaseDeviceTask` in `device/include/base_device_task.h`) and, where hardware init is nontrivial, a `bridge_*` free function that wires the vendor driver to a HAL peripheral handle (see `bridge_bme680.cpp`, `bridge_particle.cpp`).
- **BaseDeviceTask contract:** every sensor task class implements `configure(...)` (hardware bring-up, returns success) and `[[noreturn]] taskLoop()`. `setup()` binds the FreeRTOS thread ID and the shared message queue handle.
- **Shared message queue:** all sensor tasks publish readings onto one FreeRTOS queue (`SensorEventsHandle`) as `CommonMessage` (`Core/Inc/event_message.h`) — a tagged union (`UniqueID` + payload struct per sensor, defined in `event_data.h`). `mainSensorsMsgLoop` in `cpp_main.cpp` is the single consumer that dispatches on `msg.id`. Aggregate/derived sensor state (temperature, IAQ, O3, PM2.5/PM10, etc.) is collected into `CollectedAirData` (`Core/Inc/collected_data.h`).
- **AC phase control (hardware real-time path, bypasses RTOS):** `HAL_GPIO_EXTI_Callback` in `cpp_main.cpp` fires on the zero-cross interrupt (`ZC_INPUT_Pin`), resets `TIM3`, and arms an output-compare interrupt with the current `motor_speed_delay` — this is the direct ISR-to-timer path that fires the TRIAC gate; it does not go through the message queue or a FreeRTOS task.
- **Vendor drivers** (`Drivers/BME68x`, `Drivers/BSEC`, `Drivers/SPS30`, `Drivers/BSP`, `Drivers/CMSIS`, `Drivers/STM32F4xx_HAL_Driver`) and third-party middleware (`Middlewares/Third_Party`, FreeRTOS) are pulled in as-is; treat them as read-only unless specifically asked to update a driver.
- **Debug tracing:** `device/include/logger.h` provides `METHODTRACE`/`METHODLOG`/`METHODLOGF` macros (no-ops outside Debug builds) built on header-only `fmt` (fetched via `FetchContent` only in Debug builds — Release has no `fmt` dependency).
